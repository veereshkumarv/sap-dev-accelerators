# sales-orders

CAP service **SalesOrdersService** (Sales Orders), generated by `create-cap-app` from the
SAP dev accelerators golden path.

## Run

```sh
npm install
npm run watch        # cds watch with mocked users and in-memory SQLite
```

Mocked users (development and tests only):

| User  | Roles  |
|-------|--------|
| alice | Admin  |
| bob   | Viewer |

The service is served at `/odata/v4/sales-orders`; liveness at `/health`, readiness at `/ready`.

## Check

```sh
npm run lint         # ESLint with CAP rules
npm test             # node:test + cds.test, coverage threshold enforced
npm run policy       # CAP clean-core / security policy (fails on new Blocker/Critical)
npm run check        # all of the above
```

## Guardrails

- Authorization is mandatory: every entity has `@restrict`, every service `@requires`.
- No credentials or endpoints in code: remote systems are reached through destinations
  (`credentials.destination` in the `[production]` profile).
- Every file starts with a *What / Why / If missing* header; see `docs/files.md`.
- Policy exceptions only through the central `exemptions.yaml` (owner, approver, expiry).

## Deploy (Cloud Foundry)

```sh
npx mbt build -t mta_archives
cf deploy mta_archives/sales-orders_1.0.0.mtar
```

After deployment assign the role collections generated from the `Viewer` and `Admin`
role templates in the BTP cockpit.
